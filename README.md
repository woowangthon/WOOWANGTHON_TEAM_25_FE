# 우왕톤 Chrome 확장 프로그램

현재 전달 버전은 **0.7.0**, 최소 Chrome 버전은 **105**입니다. `chrome://extensions`에서 버전과 로드한 폴더를 확인하세요. 이전 확장이 함께 있으면 비활성화하고 새 FE 폴더를 로드합니다. 서버에서 시연을 켜면 팝업이 자동으로 제한된 토큰을 받아 검사합니다. 시연이 꺼져 있으면 기존 일반 계정 로그인 화면을 사용합니다. **어느 방식이든 토큰과 검사 권한을 확인하기 전에는 현재 탭을 읽거나 검사 요청을 보내지 않습니다.**

현재 화면과 같은 사이트의 공개 안내를 읽고, 판매대금·수익금 수령 전에 별도 입금을 요구하는 문구를 검사합니다. 사업자정보 최대 50점과 AI 분석·사이트 관찰 최대 50점, 합계를 나눠 표시하며 출금 조건 관찰 결과를 함께 보여줍니다. GitHub 원격에는 변경을 쓰지 않았습니다.

## 시연 사용자 — FE 전용 ZIP

관리자가 시연 서버를 켠 상태에서 다음 순서로 사용합니다. 사용자 PC에는 Python·Django·Redis·API 키·개인 로그인 준비가 필요하지 않습니다.

1. FE 전용 ZIP을 풀고 `manifest.json`이 있는 FE폴더를 확인합니다.
2. Chrome의 `chrome://extensions`에서 개발자 모드를 켜고 **압축해제된 확장 프로그램 로드**로 그 폴더를 선택합니다. 버전0.7.0을 확인하고 이전 확장은 비활성화합니다.
3. 검사할 사이트를 연 뒤 확장 팝업을 엽니다. 운영 서버는 `https://yeong.dev/woowang`입니다. 별도 시연 시작 버튼이나 계정 입력 없이 이용 가능 여부를 확인하고 검사1회를 실행합니다. 이미 유효한 일반 계정 세션이 있으면 그대로 사용합니다.
4. 시연 종료·등록 한도·호출 제한 안내가 나오면 관리자에게 서버 상태를 확인합니다. 서버가 계속 실행 중이어야 하며, 이 주소에서 확장 화면을 제공하는 웹페이지는 열리지 않습니다.

시연은 기본 OFF이고 관리자가 최대4시간의 UTC 절대 종료 시각을 설정합니다. 브라우저 설치 UUID 등록은 최대20개, 시연 전체 검사는 최근24시간100회입니다. 사용자별 분당5회·시간당30회·하루100회와 전체·동시 요청 제한도 적용됩니다. UUID는 물리적 PC를 증명하는 값이 아니며 프로필·저장소를 초기화하면 새 등록 슬롯을 소비합니다. 과거 등록 계정도 한도에 남으므로 저장소 초기화를 해결 방법으로 사용하지 마세요.

서버 운영 절차는 **관리자용 FE+BE ZIP의 `WOOWANGTHON_TEAM_25_BE/docs/LIGHTSAIL.md`**에 있습니다. FE 전용 ZIP에는 BE와 해당 가이드가 없으며, 사용자는 서버를 직접 실행할 필요가 없습니다.

## Lightsail 운영 서버에 연결

eNVy와 같은 서버에 우왕톤 API를 따로 실행하는 관리자 절차는 위 관리자용 ZIP의 Lightsail 배포 가이드를 따릅니다. eNVy 로그인이나 DB를 합치지 않습니다. 운영 API 기본 주소는 **`https://yeong.dev/woowang`**이며 새 하위 도메인을 만들지 않습니다. 확장은 `/woowang` 경로를 유지하여 `https://yeong.dev/woowang/api/v1/auth/login/`, `https://yeong.dev/woowang/api/v1/scan/`으로 요청합니다. 서버 내부 연결은 eNVy의 8000 포트와 겹치지 않는 8002 포트를 사용합니다.

확장에 허용된 기본 주소는 운영 `https://yeong.dev/woowang`과 로컬 개발 `http://127.0.0.1:8000` 두 개입니다. 기존 세션 저장 필드 이름 `apiOrigin`은 호환을 위해 유지하지만 이제 `/woowang`을 포함한 전체 기본 주소를 담습니다. 임의 서버나 다른 경로로 비밀번호·토큰을 보내지 않습니다. 이전 운영 주소의 세션은 재사용하지 않습니다. 새 주소에서 활성 시연 자동 등록 또는 일반 계정 로그인으로 새 토큰을 받습니다.

유효한 세션이 없으면 선택된 서버의 `GET /api/v1/auth/demo/`를 먼저 확인합니다. `enabled`, `reason`(`active`·`disabled`·`expired`), `expires_at`, `max_devices`, `daily_limit` 응답을 확인하고 활성 상태에서만 안정적인 UUIDv4를 `chrome.storage.local`에 저장해 `POST /api/v1/auth/demo/`의 `device_id`로 보냅니다. UUID는 비밀값이 아니고 API 키·토큰도 아닙니다. 운영에서는 각 경로 앞에 `/woowang`을 붙이며 로컬8000도 같은 계약입니다.

시연이 꺼져 있으면 관리자가 개인별 검사 계정을 발급한 뒤 확장 로그인 화면에서 **우왕톤 서버**를 선택하고 로그인합니다. 상시 공개 회원가입과 공용 고정 토큰은 없습니다. 팝업은 확장의 `host_permissions`로 허용된 API에 요청하므로 PC마다 압축해제 확장 ID를 CORS에 등록할 필요는 없습니다. 서버의 `DJANGO_CORS_ALLOWED_ORIGINS`에는 별도 웹 클라이언트의 정확한 출처를 허용합니다(운영 예시 `https://yeong.dev`). `/woowang` 경로나 `*`를 넣지 않고, 필요하면 정확한 `chrome-extension://확장ID`를 추가합니다. CORS 허용은 토큰 인증을 대신하지 않습니다.

일반 로그인 토큰은30분 뒤 만료되며 자동 갱신하지 않습니다. 시연 응답의 `token`, `expires_at`, `user`, `mode: "demo"`, `demo_expires_at`을 확인하며 데모 토큰은 최대30분이고 서버의 절대 시연 종료 시각을 넘지 않습니다. 시연 비활성화·기간 종료 시에는 개별 토큰 TTL이 남아 있어도 서버가 거절합니다. 토큰은 확장 전용 `chrome.storage.session`에만 보관하고 비밀번호를 저장하지 않습니다. `GET /api/v1/auth/me/` 검증 후 현재 탭을 읽고 검사1회를 실행합니다. 유효한 일반 계정 세션을 데모로 바꾸지 않습니다. 서버 API 키를 확장 코드나 설정에 넣지 않습니다. 로그아웃은 브라우저의 로그인 정보·관찰 기록을 즉시 지우고 서버에 토큰 폐기를 요청합니다. 서버 연결이 실패하면 그 사실을 표시하며 서버 토큰은 만료되거나 관리자가 폐기할 때까지 남을 수 있습니다. 계정이나 서버를 바꾸면 이전 사용자의 화면·기록을 재사용하지 않습니다.

일반 계정의401·403이면 다시 로그인하거나 관리자에게 검사 권한을 확인합니다. 시연 종료·비활성화 안내는 관리자가 시연 창을 확인해야 합니다. 429이면 표시된 시간 후 **직접 다시 검사**하며 자동 재요청하지 않습니다. 503이면 서버의 접근 보호 기능을 사용할 수 없는 상태이므로 잠시 후 다시 시도합니다. 사용자 답변이나 원문으로 확인한 입금 경고는 인증 만료·서버 오류만으로 해제하지 않습니다. 명시적인 로그아웃·계정 변경·기록 지우기는 기록을 제거합니다.

## 동작과 범위

- 일반 또는 데모 토큰 검증 후 기존 현재 탭 검사 한 번에서 사업자정보, 보이는 메뉴, 관련 안내문과 공개 안내 링크를 추출합니다. 충전 신청·출금 신청·정산 메뉴가 보이면 검사 응답 전에 질문과 세 답변을 표시합니다.
- 메뉴 없이도 세금 납부·수익금 지급·보증금·계정 해제·보상·적립 안내를 수집합니다. 현재 화면은 보이는 문구만 읽으며 입력·선택·편집 영역을 제외합니다. 계좌·전화번호와 개인 잔액은 마스킹합니다.
- 보이는 링크 중 같은 출처(프로토콜·호스트·포트)의 공개 출금·환급·정산 안내를 최대 2개 GET으로 읽습니다. 인증 쿠키를 보내지 않고 로그인·회원가입·거래 동작·민감한 쿼리·외부 링크·리디렉션을 따라가지 않습니다. 페이지당 3초·160KiB로 제한하며 재귀 탐색하지 않습니다.
- 받은 HTML은 inert template로 읽어 스크립트·폼·이미지를 실행하지 않습니다. 외부 CSS나 JavaScript 렌더링을 재현하지 않으므로 공개 정적 안내의 관찰 결과이며, 로그인 이후 화면·iframe·shadow DOM·외부 고객센터 대화까지 확인했다는 뜻이 아닙니다.
- 현재 문구·공개 안내·이전 관찰을 `page_observations`로 함께 보냅니다. 문구 합계는 최대 2,000자이며 `page_context`도 호환용 선택 문자열로 보냅니다. 출처 ID·URL·관찰 시각을 유지합니다.
- 같은 사이트에서 팝업을 열어 관찰한 **보상 안내 → 수익·적립 표시 → 출금 제한 → 추가 입금 요구**를 연결합니다. `chrome.storage.session`에 사용자·서버별로 구분한 마스킹 안내와 답변을 최대 2시간 보관합니다(사이트 최대 20개, 저장 문구 최대 8개/사이트). 브라우저 세션 종료·로그아웃·계정 변경·기록 지우기로 제거됩니다. 팝업을 열지 않은 화면은 자동 추적하지 않습니다.
- 직접적인 입금 조건은 이전 단계 기록 없이도 경고합니다. `ADVANCE_PAYMENT_REQUIRED`의 인용문이 **해당 출처로 실제 전송한 원문**에 있고 출처 ID·URL도 일치할 때만 경고와 근거 주소를 표시합니다. 조작된 인용문·다른 출처의 인용은 표시하지 않습니다.
- 모델 성공 결과와, 백엔드가 별도로 검증한 `source: "rule"`의 명시적 요구를 구분합니다. AI가 `skipped`/`error`여도 검증된 규칙 근거는 경고할 수 있습니다. 사용자의 **먼저 보내라고 했어요** 답변은 API 실패·지연 응답·팝업 재열기로 해제되지 않습니다.
- 확인되지 않은 단계는 항상 **출금 조건 미확인**입니다. 보상·잔액·출금 제한 또는 낮은 사업자 위험 점수만으로 선입금 요구가 없거나 출금이 안전하다고 판단하지 않습니다.

## 공지·후기·메뉴 가점

| 관찰 조건 | AI 영역 원점수 |
|---|---:|
| 공개 범위에서 공지사항을 찾지 못하거나 빈 공지 목록 | 50 |
| 확인 가능한 최신 공지가 최근1개월보다 오래됨 | 50 |
| 현재 화면에 보이는 출금신청 또는 충전신청 메뉴 | 40 |
| 공개 범위에 구매후기를 찾지 못하거나 빈 후기 목록 | 40 |

공지 없음50 + 후기 없음40 = 원점수90이지만 **최종 AI 점수는50점**입니다. 메뉴40까지 합쳐130이어도50점만 반영합니다. 원점수·상한 적용·항목별 반영 점수를 함께 보여줍니다. 기존 직접 선입금50과 단계 조합10도 동일한 AI 상한 안에서 계산합니다.

메인 화면에 출금신청·충전신청 버튼이나 링크가 보이면 연결 페이지가 로그인으로 막혀도 메뉴40점은 반영합니다. 숨겨진 메뉴·본문의 단어·정산 메뉴만으로 새40점을 만들지 않습니다. 메뉴 자체는 직접적인 입금 요구가 아니므로 그것만으로 빨간 입금 경고를 띄우지 않습니다.

현재 렌더링된 화면과 같은 출처의 공지·후기 페이지를 각각 최대1개씩 추가로 확인합니다(기존 지급 안내2개와 별도, 합계 최대4개). 각 요청은 쿠키 없이 최대3초·160KiB이며 리디렉션·가입·쓰기·주문·고객센터 대화를 따라가지 않습니다. 명시적인 빈 목록·후기0건과 접근 실패를 구분합니다. 공지 날짜는 게시 목록에서 읽고 저작권 연도나 화면 시계를 쓰지 않습니다. 읽지 못한 목록·확인할 수 없는 최신 날짜는 미확인입니다.

`site_checks`는 제한된 관찰 상태·날짜·출처를 전송하며 입력값·계좌·전화·후기 작성자 내용을 보내지 않습니다. 지급 문구의2,000자 제한이나 세션 기록에 섞지 않으며 매 검사 새로 읽습니다. 공지·후기 없음은 확인한 공개 범위의 관찰이고 사이트 전체를 검색했다는 뜻이 아닙니다. 점수는 백엔드 규칙으로 계산하며 `site_rule`로 모델 판단과 구분합니다.

## 50 + 50 점수 표시

사업자정보 최대 50점과 AI 분석·사이트 관찰 최대 50점, 합계를 나눠 표시합니다. 최상위 `risk_score`는 서버가 이미 합산한 값이며 프런트엔드는 다시 점수를 더하지 않습니다. 사업자 원점수 70점과 55점은 각각 상한 50점을 반영합니다. 위험 근거에는 상한 적용 전후 점수를 함께 표시합니다.

검증된 직접 입금 요구는 AI 50점, 보상·수익 표시·출금 제한 전체 조합은 10점입니다. 중복 합산하지 않으며 직접 요구는 합계가 50점이어도 높은 위험 경고를 유지합니다. 모델을 쓰지 못해도 확인된 사이트 규칙 가점은 반영하며 `rule_only`로 구분합니다. 알려진 점수 근거가 없고 분석할 수 없으면 `null`/미확인입니다. 사용자 직접 답변은 팝업 경고로 유지하며 AI 점수로 바꾸지 않습니다. 점수는 사기 확률이 아닙니다.

번호가 잘못 표시된 경우 정확한 표시 원문을 선택 `business_info.displayed_business_number`로 보내고, 숫자 자릿수와 함께 팝업에 보여줍니다. 번호 오류20점 + 공정위 상호명 조회 실패25점 + 두 조건의 조합 가산5점 + AI0이면50점입니다. 두 조건이 함께 확인될 때만 조합 가산점을 반영하고 각각의 단독 가중치는 유지합니다. 원문을 임의로 자르거나 정상 번호로 만들지 않습니다.

BE는 GitHub main의 복수 대표자 비교를 통합했습니다. 팝업에서도 `PARTIAL_MATCH`를 ‘일부 일치’로 표시하며 전체 일치로 표시하지 않습니다.

이전 API의 40+60 또는 60+40 응답도 원래 숫자대로 표시하고 정책이 오래됐다는 안내를 보여줍니다. `score_breakdown` 자체가 없으면 기존 사업자 점수 응답임을 알립니다. 이전50/50 v1·v2 응답도 원래 점수대로 표시하고 새 사이트 관찰 규칙을 위해 백엔드 갱신을 안내합니다. 새 정책 `business50_ai50_v3`를 쓰려면 FE와 BE를 함께 갱신하고 Django를 재시작하세요.

## Windows PC에서 실제 Django 연결

관리자용 ZIP의 두 폴더를 나란히 유지합니다. 아래는 시연을 켜지 않은 로컬 개발의 일반 계정 방식이며, 운영 배포는 관리자용 Lightsail 가이드를 사용합니다. 확장 로그인 화면에서 **로컬 개발 서버**(`http://127.0.0.1:8000`)를 선택합니다. 인증과 호출 제한은 로컬에서도 적용되므로 Redis와 검사 계정이 필요합니다. 관리자가 로컬 시연을 명시적으로 켠 경우에는 같은 API 계약으로 자동 등록하며 일반 계정 준비를 대신할 수 있습니다.

1. ZIP을 풀고 BE 폴더의 새 PowerShell에서 가상환경을 준비합니다. 기존 Cloud `.venv`나 운영 서버 환경변수를 복사하지 않습니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

2. Docker Desktop을 실행한 뒤 로컬 Redis를 루프백에만 연결합니다. 이미 같은 이름의 컨테이너를 만든 경우에는 새로 만들지 않고 `docker start woowang-local-redis`로 시작합니다.

```powershell
docker run --name woowang-local-redis --detach --publish 127.0.0.1:6379:6379 redis:7.4-alpine redis-server --appendonly yes --maxmemory 64mb --maxmemory-policy noeviction
$env:WOOWANG_PRODUCTION = "false"
$env:WOOWANG_REDIS_URL = "redis://127.0.0.1:6379/0"
```

이 Redis 명령은 개인 PC의 로컬 개발용입니다. 운영 서버는 배포 가이드의 비밀번호·볼륨·별도 네트워크 구성을 사용합니다. Redis가 없으면 검사가 503으로 차단되며 인증을 끄는 옵션은 제공하지 않습니다.

3. Chrome `chrome://extensions`에서 개발자 모드를 켜고 **압축해제된 확장 프로그램 로드**로 FE 폴더를 선택합니다. 업데이트라면 새로고침하고 버전0.7.0과 storage 권한을 확인합니다. 확장만 사용한다면 PC별 ID의 CORS 등록은 필요하지 않습니다. 별도 웹 클라이언트를 허용할 때만 같은 BE 터미널에서 정확한 출처를 설정합니다. 아래는 선택 예시이며 설정 파일을 직접 수정하지 않습니다.

```powershell
$env:DJANGO_CORS_ALLOWED_ORIGINS = "https://yeong.dev"
```

4. 실제 분석이 필요하면 같은 터미널에 `OPENAI_API_KEY`를 비표시 입력으로 설정합니다. `OPENAI_MODEL` 기본값은 `gpt-6-luna`입니다. 실제 공공 API는 `NTS_SERVICE_KEY`, `FTC_SERVICE_KEY`가 필요합니다. 키를 코드·명령 인자·로그에 쓰지 않습니다. 키가 없어도 로그인과 모의 페이지의 규칙 분석은 확인할 수 있습니다.

5. 마이그레이션 후 개인별 검사 계정을 만듭니다. 비밀번호는 명령 실행 뒤 비표시 입력창에서 입력하며 12자 이상이어야 합니다. 이미 만든 계정은 다시 생성하지 않습니다.

```powershell
.\.venv\Scripts\python.exe app\manage.py migrate
.\.venv\Scripts\python.exe app\manage.py create_scanner scanner_local
.\.venv\Scripts\python.exe app\manage.py runserver 127.0.0.1:8000 --noreload
```

6. FE 폴더의 터미널 2에서 **페이지 서버만** 실행합니다.

```powershell
python -m http.server 4173 --bind 127.0.0.1
```

`npm run mock`은 모의 API의 8000 포트도 사용하므로 Django와 동시에 실행하지 않습니다. 두 서버를 함께 쓰려면 페이지는 위 4173 명령으로 제공하세요.

7. 아래 주소에서 팝업을 열고 **로컬 개발 서버**와 위에서 만든 개인 계정으로 로그인합니다. 활성 시연을 사용하는 경우에는 자동 등록합니다. 유효한 토큰 검증 전에는 질문 카드도 검사 결과도 표시하지 않습니다. 검증 후 같은 사이트의 이전 경고가 남아 있다면 **이 사이트 기록 지우기**를 누르고 팝업을 다시 엽니다. 독립 사례 사이에는 기록을 지우고, 단계 연결 확인 중에는 유지합니다.

| 4173 뒤 주소 | 확인할 동작 |
|---|---|
| `/tests/fixtures/flow-stage.html?stage=menu` | 메뉴만 있으면 질문 표시, 출금 조건 미확인 |
| `/tests/fixtures/flow-home.html` | 홈의 공개 출금 안내까지 읽고 경고·원문·`flow-policy.html` 출처 표시 |
| `/tests/fixtures/flow-stage.html?stage=tax` | 세금 납부 조건을 이전 기록 없이 경고 |
| `/tests/fixtures/flow-stage.html?stage=deduction` | 수수료 차감만으로 자동 경고 없음, 출금 조건 미확인 |
| `flow-stage.html?stage=reward` → `earnings` → `restricted` → `tax` | 각 단계에서 팝업을 열고 닫아도 이전 관찰 유지, 마지막 조건에서 경고 |

실제 모델 호출에는 비용이 발생합니다. 반복해서 팝업을 열면 호출이 추가됩니다. 키가 없는 서버에서도 명시적 입금 조건의 규칙 경고는 확인할 수 있으므로, 경고 표시만으로 OpenAI가 성공했다고 판단하지 마세요. 팝업 개발자 도구 Network에서 `analyses.ai.status === "completed"`와 `signals[].source === "ai"`를 확인합니다. `source === "rule"`은 모델 분류 결과가 아닙니다.

## 외부 API 없는 화면 확인

FE 폴더에서 `npm ci` 후 `npm run mock`을 실행하면 합성 페이지 4173과 모의 API 8000이 열립니다. **실제 Django를 종료한 상태에서** 사용합니다. 확장 로그인 화면에서 **로컬 개발 서버**를 선택하고 사용자명 `demo`, 비밀번호 `Local-demo-only-2468!`로 로그인합니다. 이 값은 로컬 모의 서버 전용 합성 계정이며 실제 Django·운영 서버 계정이나 v0.7.0의 서버 제어 시연 등록으로 사용하지 않습니다. Redis와 외부 API 키는 필요하지 않습니다.

위 주소들을 그대로 사용하며 OpenAI·국세청·공정위는 호출하지 않습니다. `?mock=hallucination`은 전송하지 않은 인용문을, `?mock=fail`은 지연 실패를 반환합니다. 쿼리가 있는 주소에서는 `&mock=fail`처럼 붙입니다. 실제 백엔드 연결 확인에는 `npm run mock` 대신 앞 절의 Django8000 + 페이지4173 조합을 사용합니다.

## 테스트

```sh
npm ci
npx playwright install chromium
npm test
```

`CHROMIUM_EXECUTABLE_PATH`로 시스템 Chromium 경로를 지정할 수 있습니다. `/usr/bin/chromium`이 있으면 자동 사용합니다. 실제 Django HTTP 통합 테스트는 인접 BE와 `.venv`를 사용하며 다른 위치는 `BACKEND_ROOT`, `BACKEND_PYTHON`으로 설정합니다. BE 환경이 없으면 통합 테스트가 생략되므로 결과에서 skipped 수를 확인합니다.

테스트는 실제 Chromium DOM과 로컬 Django HTTP를 사용하되 Chrome 확장 API와 외부 OpenAI·공공 API를 모의 처리합니다. Cloud는 관리자 확장 설치 정책 때문에 설치형 Chrome 검증을 수행하지 못했습니다. 이번 개선의 실제 모델 분류 정확도는 검증하지 않았습니다. 최종 실행 개수와 결과는 통합 ZIP의 `TEST_RESULTS.json`에 기록합니다.

주요 파일은 `auth.js`(허용 서버·일반 로그인·자동 시연 등록·세션 토큰·인증 요청), `popup.js`(인증 후 추출·요청·렌더링), `flow.js`(공개 안내와 사용자별 세션 기록), `popup.html`(로그인·질문·근거·미확인 안내), `manifest.json`(버전·storage 권한), `tests/auth.spec.js`(인증·경고 유지·계정 분리), `tests/flow.spec.js`, `tests/backend.spec.js`(실제 로컬 Django HTTP 연동)입니다.

모의 `visible.html`의 사업자번호는 실제 등록을 검증하기 위한 번호가 아닙니다. 실제 공공 API를 연결하면 국세청 미등록 30점과 공정위 사업자번호 검색 실패 40점이 함께 확인되면 사업자 영역 상한 50점이 반영됩니다. 실제 응답에 따라 달라지며 선입금 신호와 구분해서 봅니다. 국세청의 상태 설명이 빈 문자열이어도 팝업에 빈칸으로 남기지 않습니다.

메뉴 이름의 나열(예: 보상 | 적립 | 제한 | 세금 조건)은 거래 단계 근거로 보내거나 기록하지 않습니다. 이전 버전에 저장된 메뉴 문구도 재사용 전에 걸러냅니다. 단계 목록은 관찰 순서를 뜻하지 않으며, 확인 시각은 출처별 기록에서 확인합니다. 직접 답변에 따른 경고에는 별도 안내를 표시합니다.

공개 안내 조회는 최대 2개로 유지하면서 출금·환급 안내와 공개 이용안내·약관을 충전 신청·출금 내역보다 먼저 선택합니다. 조회 결과에는 각 페이지 주소와 로그인 필요·시간 초과·크기 제한 등의 이유를 표시합니다. 분석할 안내문 미수집과 서버 AI 키 미설정도 구분합니다. 로그인 제한을 우회하거나 가입을 요청하지 않습니다. 같은 출처 ID·URL에서 바깥 괄호·따옴표·공백만 다른 중복 근거는 원문을 수정하지 않고 하나만 표시합니다.

새 main의 ScanCache 초기 마이그레이션을 포함합니다. 업데이트 뒤 기존 DB를 유지한 채 migrate를 실행하세요. 사업자 조회 결과만 24시간 이내 캐시에서 재사용하며 팝업에 재사용 여부를 표시합니다. 같은 URL이어도 현재 안내문과 AI 점수는 매번 새로 검사합니다.
